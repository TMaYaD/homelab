# Home Assistant GitOps

Strategy and requirements for bringing the HAOS instance (`haos-pi`, 10.10.11.6)
under GitOps. The desired-state root is **`home-assistant/config/`**, which maps
1:1 onto `/config` on the pi. The k8s manifests at the `home-assistant/` top
level are preserved from the old in-cluster deployment and are not part of the
GitOps surface.

## Model

ArgoCD semantics, adapted for HA:

- **Git is desired state.** The pi is live state and never auto-commits back.
- **Apply**: new commits are pulled by a reconciler add-on on the pi
  (sparse-checkout of this folder), secrets decrypted, `ha core check`,
  targeted reload (full restart only when required).
- **Detect**: live state is continuously diffed against the git worktree.
  Drift is surfaced (ingress web UI with per-file diffs, a drift sensor
  entity, persistent notification) — never silently committed, never
  silently stomped. Local drift + incoming git change on the same file
  is a conflict, surfaced to the human.
- **Act** (human-initiated, per drifted item): **revert** (re-apply git
  state to the pi), **promote** (commit live state to `main` with a
  user-written message), or **ignore** (persistent rules for known-noisy
  paths, à la ArgoCD `ignoreDifferences`).

The reconciler is a custom HAOS add-on (separate repo, TBD) — existing
tools (git-ha-ppens, Git Pull, Git Exporter) were evaluated and rejected:
none support a monorepo subfolder, and their secrets story is exclusion
or censoring, not encryption.

## Config surface tiers

**Tier assignment is by best available representation, not by where a
value currently lives.** The click-ops rebuild parked things in
`.storage` that HA still accepts in YAML (e.g. the `homeassistant:` core
block — location, elevation, unit system, timezone); those are Tier 1
and get re-materialized into YAML, which also makes the corresponding UI
settings read-only — converting the domain back to gitops permanently.
Tier 3 is reserved for state with genuinely no YAML form.

- **Tier 1 — plain YAML** (`configuration.yaml`, `automations.yaml`,
  `scenes.yaml`, `scripts.yaml`, includes, `blueprints/`): direct file
  diff. UI-created automations/scenes/scripts land here natively, so the
  most common click-ops is covered with zero translation.
- **Tier 2 — `.storage` JSON with a faithful YAML form**: translated to a
  canonical YAML projection and diffed against a git-tracked file.
  Dashboards run in **storage mode** (decided 2026-07-06): the UI editor
  is the draft workspace, git is the merge gate. Projections live in
  `config/dashboards/`. Promote = commit projection; revert = write back to
  `.storage` via the HA websocket API. Helpers get the same treatment
  when any exist (none today).
- **Tier 3 — `.storage` with no official YAML form** (config entries,
  device/entity/area/floor/label registries, HACS state): surfaced as
  normalized, secret-redacted diffs against a committed baseline
  snapshot; the only action is "acknowledge baseline". Not appliable.

### Tier 3 custom representations (requirement, 2026-07-06)

Once the base reconciler works, build **our own YAML representation for
Tier 3 values where a meaningful one exists** — e.g. floors and labels
(names, icons, area membership) — while excluding machine-internal
fields (ids, created/modified timestamps, entry ids). The representation
must be:

- deterministic (stable ordering, so diffs are meaningful),
- lossless for the fields it covers (promote/revert round-trips cleanly
  via the websocket API where HA allows writes),
- explicit about what it does NOT cover (fields dropped from the
  projection are, by definition, not under GitOps).

This upgrades selected Tier 3 domains to Tier 2 over time. Candidates in
rough order: floors, labels, areas, dashboard registry (sidebar
title/icon/url), HACS installed-package manifest (name + version pin).

## Secrets

- SOPS + age, value-level encryption (keys/structure stay plaintext —
  surgical, sealed-secrets-equivalent). No whole-file encryption.
- `/config/secrets.yaml` (plaintext, pi only) ⇄ `home-assistant/config/secrets.sops.yaml`
  (SOPS-encrypted values) in git. The distinct filename keeps the
  `secrets.yaml` gitignore guard intact so plaintext can never be committed
  by accident; the reconciler translates the name on apply/promote.
- Two age recipients: the pi's key and an operator key (password manager)
  so secrets are editable from either end and the pi is not a single point
  of decryption failure. The pi key is generated by the reconciler add-on
  on first start (sealed-secrets style — the private key never leaves the
  pi, lives in the add-on data dir, never in git); its public key is then
  appended to `.sops.yaml`. Note: the SSH add-on's `homeassistant` user
  has read-only `/config`, so all pi-side writes go through the add-on or
  the HA websocket API, never plain SSH.
- Leak-scan pre-commit on promote: hardcoded credentials in any YAML file
  block the promote and suggest a `!secret` extraction.

## BCDR

- Git: declarative config with full history (this folder).
- HA built-in automatic encrypted backups, shipped off the pi (NAS /
  cloud), cover `.storage`, add-on data, and everything git doesn't.
- Restore: reflash HAOS → restore backup (integrations, auth, add-ons
  including the reconciler) → reconciler pulls git and converges the
  YAML surface. Only out-of-band artifact: the age key in the password
  manager.

## Decisions log

  surfaced, human promotes or reverts.
- 2026-07-06 — Dashboards: storage mode + Tier 2 projections (UI as
  draft workspace).
- 2026-07-06 — Promotes commit directly to `main` (single-operator
  homelab; PR layer can be added later).
- 2026-07-06 — `.storage` stays out of git except via Tier 2/3
  projections; raw state is covered by backups.
- 2026-07-06 — Tier 3 custom representations requirement added (see
  above).
- 2026-07-06 — GitOps root moved to `home-assistant/config/`; the k8s
  manifests from the old in-cluster deployment are preserved at
  `home-assistant/` (kustomization updated to the new config path).
- 2026-07-06 — Alexa is served via the Matter bridge; the old `alexa:`
  YAML block (and its client-id/secret) stays retired.
- 2026-07-06 — The `homeassistant:` core block is Tier 1 and will be
  re-materialized in `configuration.yaml` (lat/long/elevation via
  `!secret` → first real entries in `secrets.sops.yaml`); current values
  to be read via `GET /api/config` once an access token is available,
  since `.storage/core.config` is root-only on the pi.
